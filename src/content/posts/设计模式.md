# 23种设计模式

什么是设计模式？

是解决问题的一系列套路，不是语法规定，而是一套提高代码可复用性的，可维护的，可读的，稳健，安全的解决方案



# 1.  代理模式

## 1.1 静态代理

我现在有个car类实现了moveable接口的move方法，让我的车动起来了，但是之后我还想加功能，比如加记录公里数，加车的性能检测

但是我不想改原有代码的情况下怎么去加这些功能呢？

```java
public interface Moveable {
    void move();
}
```

```java
public class Car implements Moveable{

    //车的牌子
    private String name;
    //什么时候买的
    private LocalDate start;
    //价格是多少
    private double price;

    Car(String name,LocalDate start,double price){
        this.name = name;
        this.start = start;
        this.price = price;
    }

    @Override
    public void move() {
        System.out.println(name+"：move...");
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public LocalDate getStart() {
        return start;
    }

    public void setStart(LocalDate start) {
        this.start = start;
    }

    public double getPrice() {
        return price;
    }

    public void setPrice(double price) {
        this.price = price;
    }
}
```

这时可以使用proxy代理模式

```java
public class Proxy01 implements Moveable{

    //代理的目标类对象
    private Car car;

    Proxy(Car car){
        this.car = car;
    }

    //计算到目前为止买了几年了
    private int nowDate(){
        LocalDate start = car.getStart();
        LocalDate now = LocalDate.now();
        return Period.between(start, now).getYears();
    }

    private void check(){
        System.out.println("检查车的性能");
    }

    @Override
    public void move() {
        System.out.println("我开了"+nowDate()+"年了");
        car.move();
        check();
    }
}
```

注意的点！

**代理类必须持有目标对象**（通过构造方法传入）

**代理和目标实现同一个接口**

**调用代理方法 = 执行增强逻辑 + 目标逻辑**

此时我又想在代理对象进行性能检测后实现环绕检测怎么办？

```java
//代理对象2实现环绕检查在性能检查后
public class Proxy02 implements Moveable{
    private Car car;

    Proxy02(Car car){
        this.car = car;
    }

    private void beforeCheck(){
        System.out.println("检查前...");
    }

    private void afterCheck(){
        System.out.println("检查后...");
    }

    @Override
    public void move() {
        beforeCheck();
        car.move();
        afterCheck();
    }
}
```

解决方案：让代理面向接口，实现**代理链**

`Proxy` 和 `Proxy02` 都直接持有 `Car`，**不能互相套**。只要改一行：**把代理里的 Car 改成 Moveable**，就能无限套娃

```java
public class Proxy01 implements Moveable{

    //代理的目标类对象
    private Moveable car;

    Proxy01(Moveable car){
        this.car = car;
    }

    //计算到目前为止买了几年了
    private int nowDate(){
        Car target = (Car)car;
        LocalDate start = target.getStart();
        LocalDate now = LocalDate.now();
        return Period.between(start, now).getYears();
    }

    private void check(){
        System.out.println("检查车的性能");
    }

    @Override
    public void move() {
        System.out.println("我开了"+nowDate()+"年了");
        car.move();
        check();
    }
}
```

## 1.2 动态代理

上面的虽然挺好的但是我不仅想让proxy代理car的move方法，我还想让他代理其他任何可以代理的类型怎么实现？

car实现了moveable接口所以我知道它一定有move方法，但我想实现动态的代理，在不知道具体方法或者没有接口怎么代理？

```java
public class Test {
    public static void main(String[] args) {
        Car car = new Car("宝马", LocalDate.of(2020,5,1),400000);
        Moveable proxy = new Proxy02(new Proxy01(car));
        proxy.move();
        System.out.println("-------------");
        Moveable o =(Moveable) Proxy.newProxyInstance(
                Car.class.getClassLoader(),
                Car.class.getInterfaces(),
                new InvocationHandler() {
                    @Override
                    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
                        System.out.println("before...check...");
                        Object o = method.invoke(car, args);
                        System.out.println("after...check...");
                        return o;
                    }
                });
        o.move();
    }
}
```

使用了JDK动态代理，JDK 动态代理**必须基于接口**，所以要传接口数组（一个类可以实现多个接口）

也可以创建一个代理类实现InvocationHandler

```java
public class Proxy03 implements InvocationHandler {
    private Object obj;

    public Object createProxy03(Object obj){
        this.obj = obj;
        Object o = Proxy.newProxyInstance(obj.getClass().getClassLoader(), obj.getClass().getInterfaces(), this);
        return o;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("before...check...");
        Object o = method.invoke(obj);
        System.out.println("after...check...");
        return o;
    }
}
```

```java
public class Test {
    public static void main(String[] args) {
        Car car = new Car("宝马", LocalDate.of(2020,5,1),400000);
        Proxy03 proxy03 = new Proxy03();
        //JDK 动态代理生成的对象，只能强转成moveable【接口类型】，不能强转成car【实现类类型】！
        Moveable car2 = (Moveable) proxy03.createProxy03(car);
        car2.move();
    }
}
```

这是spring 框架 底层之一：**JDK 动态代理** ，**CGLIB 动态代理**（不用接口，但需要目标类有无参构造方法）

```java
public class Proxy04 implements MethodInterceptor {

    private Object target;
    public Object createProxy(Object target){
        this.target = target;
        Enhancer enhancer = new Enhancer();
        //确定要增强的类设置为父类
        enhancer.setSuperclass(target.getClass());
        enhancer.setCallback(this);
        return enhancer.create();
    }

    @Override
    public Object intercept(Object o, Method method, Object[] objects, MethodProxy methodProxy) throws Throwable {

        System.out.println("before....");
        Object o1 = method.invoke(target, objects);
        System.out.println("after.....");
        return o1;
    }
}
```



# 2. 单例模式

只需要一个实例，**整个程序中，某个类**只能有且仅有一个实例对象 **，全局共享这一个对象，不能 new 多个。

核心特点

1. **构造方法私有**：`private 构造器`，外面不能随便 `new`
2. **内部自己创建唯一实例**
3. **对外提供一个静态方法**：`getInstance()` 用来拿这唯一对象
4. **全局唯一、全局共享**

为什么要用单例？

- 节省内存：不用重复创建对象
- 全局统一用同一个资源：比如 **数据库连接池、工具类、配置类、Spring Bean** 都是单例
- 控制资源只能有一份：比如打印机任务管理器、计数器



## 2.1 饿汉式

1. 类加载到内存后实例化一个单例，jvm保证线程安全

2. 简单实用
3. 缺点用不用都要实例化

```java
public class Manager {
     //唯一实例
     private static final Manager manager = new Manager();
     // 构造方法私有，无法new
     private Manager(){}

    //通过方法得到唯一对象
     public static Manager getManagerInstance(){
         return manager;
     }
}
```

```java
public class TestSingleton {
    public static void main(String[] args) {
        Manager manager = Manager.getManagerInstance();
        Manager manager2 = Manager.getManagerInstance();
        //true,拿到的对象是唯一的
        System.out.println(manager == manager2);
    }
}
```



## 2.2 懒汉式

懒加载：第一次调用才创建不用就不建，多线程下会创建多个实例，有线程安全问题，要加锁

```java
public class Manager02 {
    //static 直接暴露在内存中
    private static Manager02 manager02;

    private Manager02(){}
    public static Manager02 getInstance(){
        if (manager02==null){
            manager02 = new Manager02();
        }
        return manager02;
    }
}
```

```java
public class TestSingleton {
    public static void main(String[] args) {
        Manager manager = Manager.getManagerInstance();
        Manager manager2 = Manager.getManagerInstance();
        //true,拿到的对象是唯一的
        System.out.println(manager == manager2);

        System.out.println("-----------------");
        Manager02 manager3 = Manager02.getInstance();
        Manager02 manager4 = Manager02.getInstance();
        //true
        System.out.println(manager3==manager4);
    }
}
```

这种线程是不安全的

```java
public class Manager02 {
```

# 4. 工厂模式

## 4.1 静态工厂/简单工厂

**“工厂”**顾名思义就是造东西的，造的就是对象

为什么要用工厂创造对象？灵活控制生产过程

```java
public class Car {

    private String brand;

    public Car(String brand){
        this.brand = brand;
    }

    public void go(){
        System.out.println(brand+"跑起来...");
    }
}
```

```java
public class Plant {
    private String brand;
    public Plant(String brand){
        this.brand =  brand;
    }
    public void go(){
        System.out.println(this.brand+"起飞...");
    }
}
```

```java
public class VehicleFactory {
    //=================简单工厂=========================
    public static Car createCar(String brand){
        return new Car(brand);
    }
    public static Plant createPlant(String brand){
        return new Plant(brand);
    }
    public static Moveable createCarVehicle(String brand){
        return new Car(brand);
    }
    public static Moveable createPlantVehicle(String brand){
        return new Plant(brand);
    }

}
```

```java
public class Test {
    public static void main(String[] args) {
        Car car = VehicleFactory.createCar("宝马");
        car.go();
        Plant plant = VehicleFactory.createPlant("播音747");
        plant.go();
    }
}
```

简单工厂模式不是一个正式的设计模式，但它是工厂模式的基础。它使用一个单独的工厂类来创建不同的对象，根据传入的参数决定创建哪种类型的对象。

## 4.2 工厂方法模式

**每个产品对应一个专属工厂**，工厂也抽象化，遵循**开闭原则**。

```java
public interface AbstractFactory {
    Moveable createVehicle(String brand);
}
```

```java
public class VehicleFactory implements AbstractFactory{

    //==============抽象工厂================
    @Override
    public Moveable createVehicle(String brand) {
        return new Car(brand);
    }
}
```

```java
public class Test {
    public static void main(String[] args) {
        VehicleFactory vehicleFactory = new VehicleFactory();
        Moveable car = vehicleFactory.createVehicle("宝马");
        car.go();
    }
}
```

核心思想：**一个工厂可以创建一整套「相关产品族」**（多个不同产品）。

优点：符合开闭、单一职责

缺点：**类数量爆炸**，每加一个产品就要加一对类

## 4.3 抽象工厂

一个工厂可以创建一整套「相关产品族」

```java
// 产品等级1：手机
public interface Phone { void call(); }
// 产品等级2：耳机
public interface Headset { void listen(); }

// 小米产品族
public class XiaomiPhone implements Phone {
    @Override public void call() { System.out.println("小米手机"); }
}
public class XiaomiHeadset implements Headset {
    @Override public void listen() { System.out.println("小米耳机"); }
}

// 华为产品族
public class HuaweiPhone implements Phone {
    @Override public void call() { System.out.println("华为手机"); }
}
public class HuaweiHeadset implements Headset {
    @Override public void listen() { System.out.println("华为耳机"); }
}
```

```java
public interface AbstractFactory {
    Phone createPhone();
    Headset createHeadset();
}
```

```java
// 小米工厂：生产小米全系产品
public class XiaomiFactory implements AbstractFactory {
    @Override
    public Phone createPhone() {
        return new XiaomiPhone();
    }
    @Override
    public Headset createHeadset() {
        return new XiaomiHeadset();
    }
}

// 华为工厂
public class HuaweiFactory implements AbstractFactory {
    @Override
    public Phone createPhone() {
        return new HuaweiPhone();
    }
    @Override
    public Headset createHeadset() {
        return new HuaweiHeadset();
    }
}
```

```java
public class Client {
    public static void main(String[] args) {
        AbstractFactory factory = new XiaomiFactory();
        Phone phone = factory.createPhone();
        Headset headset = factory.createHeadset();
        phone.call();
        headset.listen();
    }
}
```

优点：统一管理**产品族**，一套产品配套创建

缺点：**新增产品等级（如平板）**，所有工厂都要改，违反开闭

| 模式     | 特点                       | 适用场景             |
| -------- | -------------------------- | -------------------- |
| 简单工厂 | 一个工厂造所有产品         | 产品少、变动不频繁   |
| 工厂方法 | 一个工厂只造一种产品       | 产品多、经常新增产品 |
| 抽象工厂 | 一个工厂造**一整套产品族** | 存在多套关联产品     |



# 5. 门面模式

门面模式也叫**外观模式**，是**结构型设计模式**，核心一句话：

**给复杂的子系统提供一个统一的简单入口，让外部调用更简单。**

门面模式 = **统一入口 + 屏蔽复杂细节 + 简化调用**

**场景：**

用户想**开机**，但开机需要：CPU 启动 → 内存启动 → 硬盘启动

不用门面：调用 3 个类

用门面：调用 1 个方法

```java
public class CPU {
    public void start(){
        System.out.println("CPU 启动...");
    }
}
```

```java
public class Memory {
    public void start(){
        System.out.println("内存 启动...");
    }
}
```

```java
public class Disk {
    public void start(){
        System.out.println("硬盘 启动...");
    }
}
```

```java
public class ComputerFacade {
    private CPU cpu;
    private Memory memory;
    private Disk disk;

    public ComputerFacade() {
        cpu = new CPU();
        memory = new Memory();
        disk = new Disk();
    }
    // 对外提供一个简单方法
    public void powerOn() {
        cpu.start();
        memory.start();
        disk.start();
        System.out.println("电脑开机完成");
    }
}
```

```java
public class Client {
    public static void main(String[] args) {
        ComputerFacade computerFacade = new ComputerFacade();
        computerFacade.powerOn();
    }
}
```

**简化调用**：客户端不用懂子系统细节

**解耦**：客户端和子系统隔离，子系统修改不影响调用方

**更好维护**：流程统一写在门面里，改一处即可

**符合迪米特法则**：最少知道原则



# 6.调停者模式

**行为型设计模式**，核心：**用一个中介对象，封装多个对象之间的交互，对象间不再直接通信，全部通过中介中转**

类比**聊天室**：

- 不用每个人互相私聊（网状复杂耦合）
- 所有人只和**聊天室（调停者）** 发消息，由聊天室转发
- 成员之间**零直接依赖**

原来：A↔B、A↔C、B↔C（耦合严重）

现在：A→中介→B/C，B→中介→A/C（单向依赖中介）

```java
//1. 抽象调停者
public interface Mediator {
    // 转发消息
    void sendMsg(String msg, Colleague sender);
}
```

```java
//2. 抽象同事类
public abstract class Colleague {
    protected Mediator mediator;

    public Colleague(Mediator mediator) {
        this.mediator = mediator;
    }
    // 接收消息
    public abstract void receive(String msg);
}
```

```java
//3. 具体同事（用户）
// 用户A
public class UserA extends Colleague {
    public UserA(Mediator mediator) {
        super(mediator);
    }
    @Override
    public void receive(String msg) {
        System.out.println("用户A收到消息：" + msg);
    }
    // 发消息，交给中介转发
    public void send(String msg) {
        mediator.sendMsg(msg, this);
    }
}

// 用户B
public class UserB extends Colleague {
    public UserB(Mediator mediator) {
        super(mediator);
    }
    @Override
    public void receive(String msg) {
        System.out.println("用户B收到消息：" + msg);
    }
    public void send(String msg) {
        mediator.sendMsg(msg, this);
    }
}
```

```java
//4. 具体调停者（聊天室）
public class ChatRoom implements Mediator {
    private UserA userA;
    private UserB userB;

    // 注入所有同事
    public void setUserA(UserA userA) {
        this.userA = userA;
    }
    public void setUserB(UserB userB) {
        this.userB = userB;
    }

    @Override
    public void sendMsg(String msg, Colleague sender) {
        // 排除发送者，转发给其他人
        if (sender == userA) {
            userB.receive(msg);
        } else if (sender == userB) {
            userA.receive(msg);
        }
    }
}
```

```java
public class Client {
    public static void main(String[] args) {
        // 创建中介
        ChatRoom room = new ChatRoom();
        // 创建用户，并关联中介
        UserA a = new UserA(room);
        UserB b = new UserB(room);
        room.setUserA(a);
        room.setUserB(b);

        a.send("大家好！");
        b.send("你好呀！");
    }
}
```

**优点**

1. **解耦**：同事之间互不依赖，只依赖中介
2. **简化关系**：多对象网状通信 → 星型结构，逻辑清晰
3. **集中管理交互逻辑**：所有协调规则统一放在中介，便于维护

**缺点**

1. **中介者会膨胀**：业务越复杂，中介逻辑越臃肿，维护难度上升
2. 同事类数量极多时，中介压力大

**五、适用场景**

1. 多个对象**存在复杂多对多交互**，耦合度高
2. 想拆分网状依赖，统一管理交互规则
3. 典型场景：聊天室、消息队列、网关、事件总线、订单多模块协同

**六、易混区分（面试高频）**

1. **调停者 vs 门面模式**
   - 门面：**单向调用**，客户端调用多个子系统，子系统之间无交互
   - 调停者：**多向交互**，多个同级对象互相通信，由中介转发
2. **调停者 vs 观察者**
   - 观察者：一对多，事件被动通知
   - 调停者：多对多，主动中转协调

七、**为什么调停者是接口，用户是抽象类？**

调停者用接口：因为我们只需要它 “做通信转发”，不关心它内部结构，追求灵活替换。

用户用抽象类：因为所有用户都必须 “持有中介 + 接收消息”，有固定结构，必须强制统一。

**调停者只管通信 → 接口最灵活。**

**用户都有中介 → 抽象类抽共性。**



# 7.装饰器模式

## 7.1 通俗理解

**结构型设计模式**，核心一句话：

**动态给对象添加额外功能，比继承更灵活、不爆炸类。**

类比你买一杯**咖啡**：

基础咖啡 = 原味

想加**牛奶** → 装饰一下

想加**糖** → 再装饰一下

想加**珍珠** → 继续装饰

**不用创建：牛奶咖啡、糖咖啡、牛奶糖咖啡…**

**而是：咖啡 + 牛奶 + 糖 动态组合！**

## 7.2 核心结构

1. **Component（抽象组件）**：定义核心方法（咖啡）
2. **ConcreteComponent（具体组件）**：基础实现（原味咖啡）
3. **Decorator（抽象装饰器）**：**持有组件引用**，和组件实现同一接口
4. **ConcreteDecorator（具体装饰器）**：加功能（加牛奶、加糖）

```java
public interface Coffee {
    // 描述
    String getDesc();
    // 价格
    double getPrice();
}
```

```java
// 基础咖啡
public class OriginalCoffee implements Coffee {
    @Override
    public String getDesc() {
        return "原味咖啡";
    }
    @Override
    public double getPrice() {
        return 10.0;
    }
}
```

```java
// 装饰器必须：实现Coffee + 持有Coffee
public abstract class CoffeeDecorator implements Coffee {
    protected Coffee coffee;

    // 构造传入被装饰对象
    public CoffeeDecorator(Coffee coffee) {
        this.coffee = coffee;
    }
}
```

```java
// 牛奶装饰器
public class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) {
        super(coffee);
    }
    @Override
    public String getDesc() {
        return coffee.getDesc() + " + 牛奶";
    }
    @Override
    public double getPrice() {
        return coffee.getPrice() + 3.0;
    }
}

// 糖装饰器
public class SugarDecorator extends CoffeeDecorator {
    public SugarDecorator(Coffee coffee) {
        super(coffee);
    }
    @Override
    public String getDesc() {
        return coffee.getDesc() + " + 糖";
    }
    @Override
    public double getPrice() {
        return coffee.getPrice() + 1.0;
    }
}
```

```java
public class Client {
    public static void main(String[] args) {
        //基础咖啡
        Coffee coffee = new OriginalCoffee();
        System.out.println(coffee.getDesc());
        System.out.println(coffee.getPrice());
        //加牛奶
        coffee = new MilkDecorator(coffee);
        System.out.println(coffee.getDesc());
        System.out.println(coffee.getPrice());
        //加糖
        coffee = new SugarDecorator(coffee);
        System.out.println(coffee.getDesc());
        System.out.println(coffee.getPrice());
    }
}
```

装饰器优势：

- **动态组合**，运行时随意加功能
- **不修改原类**，符合开闭原则
- **无类爆炸**，一个装饰器只干一件事
- **灵活嵌套**：咖啡→牛奶→糖→珍珠

天天用：

- **Java IO**：`BufferedReader` 装饰 `FileReader`
- `new BufferedInputStream(new FileInputStream(""))`
- Spring MVC：`HttpServletRequestWrapper`



# 8. 责任链

**核心思想**：将**多个处理者**连成一条链，请求沿链传递，每个处理者自行决定**处理请求**或**转发给下一个**，实现**请求发送者与接收者解耦**。

一、适用场景

1. 一个请求需要被**多个对象依次处理**，且处理对象不固定
2. 不想让请求发起者知道最终由谁处理
3. 需动态调整处理流程、增删处理节点

```java
public abstract class Handler {
    protected Handler nextHandler;

    // 设置下一个处理器
    public void setNext(Handler next) {
        this.nextHandler = next;
    }

    // 处理请求
    public abstract void handleRequest(int level);
}
```

```java
// 组长
public class GroupLeader extends Handler {
    @Override
    public void handleRequest(int level) {
        if (level <= 1) {
            System.out.println("组长审批通过");
        } else if (nextHandler != null) {
            nextHandler.handleRequest(level);
        }
    }
}

// 部门经理
public class Manager extends Handler {
    @Override
    public void handleRequest(int level) {
        if (level <= 2) {
            System.out.println("部门经理审批通过");
        } else if (nextHandler != null) {
            nextHandler.handleRequest(level);
        }
    }
}

// 总监
public class Director extends Handler {
    @Override
    public void handleRequest(int level) {
        if (level <= 3) {
            System.out.println("总监审批通过");
        } else {
            System.out.println("请求无法处理");
        }
    }
}
```

```java
public class Client {
    public static void main(String[] args) {
        // 组装责任链：组长 -> 经理 -> 总监
        Handler group = new GroupLeader();
        Handler manager = new Manager();
        Handler director = new Director();
        group.setNext(manager);
        manager.setNext(director);

        // 发起请求
        group.handleRequest(2);
    }
}
```

优点

- **解耦**：请求方和处理方隔离
- **灵活**：动态增删、调换处理节点，改变流程
- **单一职责**：每个处理器只做自己分内事

缺点

- 请求可能**遍历整条链**，性能下降
- 若链过长、逻辑复杂，调试困难
- 存在**请求无人处理**的风险

# 9. 观察者模式

**一个对象（被观察者）状态变了，自动通知所有依赖它的对象（观察者）**，一对多通知，解耦 “发布者” 和 “订阅者”。

```java
public interface Observer {
    void update(String message); // 收到通知
}
```

```java
public class Subject {
    // 观察者列表
    private List<Observer> observers = new ArrayList<>();

    // 注册观察者
    public void attach(Observer observer) {
        observers.add(observer);
    }

    // 通知所有观察者
    public void notifyAll(String msg) {
        for (Observer o : observers) {
            o.update(msg);
        }
    }
}
```

```java
public class Fan implements Observer {
    private String name;
    public Fan(String name){
        this.name = name;
    }

    @Override
    public void update(String message) {
        System.out.println(name + " 爷爷你关注的up主：" + message);
    }
}
```

```java
public class Main {
    public static void main(String[] args) {
        Subject up = new Subject();
        up.attach(new Fan("张三"));
        up.attach(new Fan("李四"));
        up.notifyAll("更新视频啦！");
    }
}
```

优点

- **解耦**：发布者不知道订阅者是谁
- **动态**：随时增删观察者
- **一对多**：一个变化，多处响应

缺点

- 观察者太多会有**性能问题**
- 通知顺序不可控
- 循环依赖会导致崩溃
